# Дополнительные спецификации BuildMate

В таблице приведены условия, которые действуют сразу в нескольких прецедентах. Значения взяты из базовой SRS v0.2 и согласованного изменения CR-001. Столбец «Проверка» задаёт критерий для реализации соответствующей итерации.

| Область и источник | Условие | Проверка |
|---|---|---|
| Роль и владелец · REQ-FUNC-002, REQ-SEC-002 | Гость подбирает и проверяет сборку. Сохранённые сборки доступны владельцу, каталог изменяет администратор. Проверка прав выполняется при каждом обращении. | Открыть чужую сохранённую сборку по идентификатору — ответ «не найдено». Обращение обычного пользователя к форме изменения каталога отклоняется. |
| Вход · REQ-FUNC-001, REQ-SEC-001, 004 | Минимальная длина пароля — 8 символов, хранение — bcrypt со стоимостью от 10. Сеанс завершается через 30 минут бездействия. Пять подряд неудачных входов блокируют вход в учётную запись на 15 минут. | После пятой ошибки ввести верный пароль сразу и после окончания блокировки. Проверить истечение сеанса. |
| Веб-интерфейс · REQ-INT-001, REQ-SEC-003 | Русские подписи при ширине 360–1920 px, текст и значок для результатов проверки, ошибки рядом с полем. HTTPS, защита форм от CSRF, экранирование вывода и параметризованные запросы. | На ширине 360 px прочитать причину нарушения без горизонтальной прокрутки. Отправка формы без действительного токена отклоняется. |
| Состав сборки · REQ-FUNC-006, 012, 019 | Для неполной сборки выводятся результаты применимых правил. Процессор без встроенной графики требует видеокарты. В подбор можно передать до восьми имеющихся деталей. | Несовпадение сокета и типа памяти даёт два отдельных нарушения. Неизвестную длину отсутствующей видеокарты система не сравнивает с пределом корпуса. |
| Мощность · REQ-FUNC-006, 007 | Основной порог — 1,3 × (P_CPU + P_GPU + 100) Вт. Для встроенной графики P_GPU = 0. Вариант «С запасом» требует коэффициента 1,6 и как минимум по одному свободному слоту памяти и M.2. | БП 550 Вт при TDP 105 и 220 Вт нарушает основной порог 552,5 Вт. При точном равенстве мощности порогу правило выполнено. |
| Производительность · REQ-PERF-001…003 | Для каталога из 5000 позиций p95 открытия страниц ≤ 1,5 с при пяти одновременных запросах на 2 vCPU и 2 ГБ ОЗУ. Для подбора p95 ≤ 5 с, для проверки совместимости и пересчёта при замене p95 ≤ 1 с. | Для подбора измерить 100 запросов на каталоге из 5000 позиций, для замены — 200 операций. |
| Цены · REQ-FUNC-010, 020, REQ-COMP-002 | У позиции видны ссылка на магазин и дата цены. Цены справочные. Цену старше семи суток помечают как устаревшую. Пересчёт BYN/USD выполняется по курсу администратора. | На седьмые сутки пометки ещё нет, на восьмые она появляется. При курсе 3 BYN за 1 USD бюджет 1000 USD даёт 3000 BYN. |
| Сохранение · REQ-FUNC-014, 015, REQ-REL-002 | Имя до 100 символов, до 50 сборок на владельца. Состав, характеристики и цены записываются одним снимком. Сравнение охватывает 2–3 конфигурации. | Изменить цену в каталоге после сохранения. Текущая цена изменится, в сравнении сохранённых сборок останется исходная. |
| Обновление каталога · REQ-INT-004, REQ-FUNC-004, CR-001 | CSV в UTF-8 содержит заголовок и поля «артикул», «цена», «наличие». Ошибочные строки пропускаются. Начальная цена и её изменения записываются в одной транзакции с позицией. | Повторить импорт прежней цены. Дата актуальности обновится, число точек графика сохранится. При отсутствии точек за 30 дней карточка показывает пустое состояние. |
| Уведомление · REQ-FUNC-017, REQ-INT-002 | При включённом отслеживании письмо с обеими суммами отправляется при изменении цены сборки в любую сторону на 5 % или более. Ограничение — одно письмо в сутки на сборку. | Для исходных 1000 BYN проверить 951, 950 и 1050 BYN. После первой отправки повтор в те же сутки подавляется. Расписание и повторы при сбое SMTP остаются открытыми вопросами плана ЛР4. |

Требования, критерии и контрольные данные приведены в [SRS](../../srs/srs.md). Правила записи точек графика приведены в [ADR-0007](../../adr/0007-component-price-history.md).
