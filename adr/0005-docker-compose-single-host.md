# Развёртывание приложения и PostgreSQL через Docker Compose

## Контекст и постановка задачи

BuildMate должен запускаться одной командой вместе с PostgreSQL, использовать настройки из переменных окружения и быть пригодным для развёртывания на Linux, macOS и Windows с Docker (REQ-INST-001). В SRS отдельно указано, что для версии 1.0 достаточно одного экземпляра приложения и одной БД.

Как обеспечить повторяемый запуск без отдельного администратора инфраструктуры?

## Драйверы решения

- Запуск приложения и PostgreSQL командой `docker compose up`.
- Секреты и адреса сервисов не включаются в исходный код.
- Простая проверка на чистом клоне репозитория.
- Возможность отката запуском предыдущего образа (REQ-INST-001).

## Рассмотренные варианты

- Локальный ручной запуск приложения и отдельно установленной БД.
- Docker Compose на одном узле.
- Kubernetes или другой оркестратор.

## Итог решения

Предлагается Docker Compose для учебного и первоначального развёртывания: контейнер приложения и контейнер PostgreSQL, постоянный том для данных и конфигурация через переменные окружения. Оркестратор не требуется текущим масштабом и не предусмотрен SRS.

### Последствия

- Хорошо: среда запуска воспроизводима и описывается в репозитории.
- Хорошо: проще проверить установку на чистой машине.
- Плохо: один узел остаётся единой точкой отказа; требование доступности 99 % требует отдельного операционного решения.
- Плохо: секреты надо безопасно задавать при развёртывании, не публикуя `.env`.

### Подтверждение

На чистой машине выполнить `docker compose up`, дождаться доступности `http://localhost:8080` за две минуты и проверить подключение к PostgreSQL (REQ-INST-001).

## Плюсы и минусы вариантов

### Ручной запуск

- Хорошо, потому что не нужен Docker.
- Плохо, потому что версии и локальные настройки легко расходятся.

### Docker Compose

- Хорошо, потому что соответствует требованию запуска одной командой.
- Плохо, потому что для production-секретов и резервных копий нужны отдельные правила эксплуатации.

### Kubernetes

- Хорошо, потому что поддерживает оркестрацию и масштабирование.
- Плохо, потому что добавляет настройку и сопровождение, не оправданные текущим SRS.

## Дополнительная информация

Связанные требования: REQ-INST-001, REQ-BUILD-001, REQ-PORT-001, REQ-REL-001, REQ-COST-001. Проектные элементы: SDD, раздел 3.5.
